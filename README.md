# Жюри конкурса «Лазурный берег»

Веб-приложение для судейства на планшетах и телефонах: оценки жюри, протоколы,
CSV, офлайн-очередь и синхронизация с сервером. Клиент — классический HTML/CSS/JS
без фреймворков и сборки. Сервер — Node.js + Express + better-sqlite3.

Конкурс: IV Всероссийский многожанровый конкурс «Лазурный берег», 11 октября 2026 г.

│   └── idb.js            LazurnyIdb: IndexedDB meta / cache / outbox

├── assets/

├── server/

│   ├── tests/            Серверные тесты (node --test)

Сервер раздаёт клиентскую оболочку сам (Express): cookie администратора и CSRF
требуют одного origin. Каталог `server/`, база данных и `.env` наружу не попадают —
статически доступны только перечисленные файлы оболочки, `client/`, `shared/` и `assets/`.

## 2. Установка и запуск сервера

Требуется Node.js 20+.

```bash
# 1. Зависимости сервера
npm install --prefix server

# 2. Конфигурация
copy server\.env.example server\.env      # Windows
# cp server/.env.example server/.env      # Linux/macOS
# отредактируйте server/.env

# 3. Первый администратор (пароль вводится интерактивно)
npm run init-admin --prefix server

# 4. Запуск API и клиента на одном порту
npm start --prefix server
```

После запуска откройте `http://localhost:3000/` (порт задаётся в `server/.env`).
Не открывайте `index.html` через `file://`: cookie, CSRF, IndexedDB и Service Worker
работают только по HTTP(S). Для локальной разработки подходит `localhost`.

### Переменные `server/.env`

| Переменная | Назначение |
|---|---|
| `NODE_ENV` | `production` или `development` |
| `PORT` | Порт сервера (по умолчанию 3000) |
| `PUBLIC_ORIGIN` | Публичный адрес сайта для ссылок в QR. Должен совпадать с адресом, по которому открывается клиент |
| `DATABASE_PATH` | Путь к SQLite относительно `server/` (по умолчанию `data/jury.db`) |
| `INVITATION_EXPIRES_AT` | Срок действия приглашений и устройств судей (до конца конкурса) |
| `SESSION_TTL_HOURS` | Время жизни сессии администратора |
| `LOGIN_MAX_ATTEMPTS`, `LOGIN_WINDOW_MINUTES` | Ограничение попыток входа администратора |
| `TRUST_PROXY` | `1`, если сервер стоит за nginx и нужно доверять `X-Forwarded-For` |

Пароль администратора в `.env` не хранится. Первичная настройка — только через
`npm run init-admin --prefix server` (интерактивно или через `ADMIN_INITIAL_PASSWORD`
в окружении процесса). В коде стартовых паролей нет.

## 3. Безопасность и доступ

### Администратор

- Пароль хранится только как Argon2id-хеш.
- Вход: `POST /api/v1/admin/auth/login {login,password}`.
- Сессия — HttpOnly cookie `lz_admin`; CSRF-токен приходит в теле ответа и хранится
  только в памяти вкладки (`LazurnyApi.setAdminCsrf`).
- При перезагрузке страница вызывает `GET /api/v1/admin/auth/session`, получает новый
  CSRF-токен (cookie переживает перезагрузку) и продолжает работу.
- Смена пароля: текущий + новый пароль (не короче 12 символов); остальные сессии
  администратора закрываются.
- Ограничение попыток входа: `LOGIN_MAX_ATTEMPTS` за `LOGIN_WINDOW_MINUTES`.

### Судья

- Паролей жюри нет. Вход — по одноразовому QR-приглашению.
- Токен приглашения: 256 бит; в базе хранится только SHA-256-хеш. Одноразовый, срок
  действия из `INVITATION_EXPIRES_AT`.
- После успешного `POST /api/v1/judge/auth {token}` сервер выдаёт `deviceToken`.
  Клиент сохраняет его и профиль судьи в IndexedDB (`meta`), а в запросах передаёт
  `Authorization: Bearer <deviceToken>`.
- Device binding: у судьи одно активное устройство (частичный уникальный индекс).
  Повторный выпуск QR отзывает активное устройство и активные приглашения, создаёт
  новое приглашение.
- Отзыв доступа: `POST /api/v1/admin/invitations/:judgeId/revoke`.
- При 401 клиент очищает `deviceToken` и профиль, показывает экран входа и
  останавливает опрос. Несохранённые элементы outbox остаются в IndexedDB с
  привязкой к judgeId и не отправляются от имени другого судьи.

### Оценки

- Идемпотентный приём по `changeId` (`score_events`): повторная отправка возвращает
  `duplicate` и не создаёт вторую запись.
- Версия оценки растёт только вверх. При одном активном устройстве порядок версий
  совпадает с порядком поступления.
- `received_at` ставит сервер; клиентское время сохраняется только в outbox.
- `criteria` — объект строго по ключам жанра, целые 1..10; лишние ключи запрещены.
- Комментарий — строка или `null`, не длиннее 2000 символов.

## 4. Клиент: состояние, офлайн и PWA

### Роли и экраны

- **Администратор:** участники, результаты, протоколы, настройки, доступ (QR).
- **Судья:** список участников своего блока, карточка оценки, комментарий, статус
  синхронизации.
- Тема оформления хранится в `localStorage` (`lazurny_jury_theme_v1`) — это не секрет.

### Состояние администратора

- После входа автоматически создаются недостающие блоки по четырём жанрам
  (названия по умолчанию). Затем клиент запрашивает `GET /api/v1/admin/state`.
- Опрос каждые 4 секунды с `?since=<revision>`. Если ревизия не изменилась, сервер
  возвращает `{changed:false}`, и клиент ничего не перерисовывает.
- Назначения судей на блоки сохраняются кнопкой через
  `PUT /api/v1/admin/blocks/:id/judges {judgeIds}`. Сервер принимает от 2 до 8 судей;
  на клиенте для удобства ограничено 4.
- После изменений (участник, судья, назначения, приглашение) клиент делает полный
  refresh состояния.

### Состояние судьи

- Вход по ссылке `?judge_token=...` или ручному токену. После успеха токен удаляется
  из адресной строки через `history.replaceState`.
- Опрос `GET /api/v1/judge/state?since=<revision>` каждые 4 секунды. Сервер отдаёт
  только блоки этого судьи, участников этих блоков, судей по блокам и его оценки.
- Если судья назначен в несколько блоков, появляется выбор блока. Если блоков нет —
  экран «Ожидайте назначения», опрос продолжается.
- Серверные оценки и локальные pending сливаются при отрисовке: pending показывается
  поверх серверной записи; серверная запись с большей версией побеждает после sync.

### IndexedDB (`LazurnyIdb`, база `lazurny_jury` v1)

| Store | Что хранится |
|---|---|
| `meta` | `deviceToken`, профиль судьи `{id, fullName}` |
| `cache` | снимок состояния судьи `{revision, state}` для офлайна |
| `outbox` | неотправленные оценки с ключом `changeId` |

Если IndexedDB недоступен (приватный режим, старый WebView), `client/idb.js`
автоматически переключается на память процесса: приложение работает, но данные не
переживают перезагрузку.

### Outbox и повторная отправка

Элемент outbox:

```js
{
  changeId,        // crypto.randomUUID() (или 32 hex-символа)
  judgeId,         // чей это черновик: защита от отправки от имени другого судьи
  participantId,   // число
  version,         // max(серверная версия пары участник+судья, max в outbox) + 1
  criteria,        // объект по ключам жанра, 1..10
  comment,         // строка или null
  createdAt,       // время устройства
  attempts,
  nextAttemptAt,   // экспоненциальная задержка
  lastError
}
```

- Сохранение оценки сразу пишет в IndexedDB и показывает «Сохранено локально».
- Отправка: батч до 50 изменений на `POST /api/v1/judge/scores`.
- `accepted` и `duplicate` удаляются из outbox; `stale` удаляется, состояние
  перезапрашивается (сервер уже записал событие, повторять нельзя); `rejected`
  удаляется, показывается ошибка, состояние обновляется.
- При сетевой ошибке: `attempts + 1`, задержка `min(60 c, 2^attempts)`; повтор по
  таймеру, при `online`, после успешного polling и при возврате на вкладку.
- Индикатор в интерфейсе судьи: «Сохранено локально» / «Отправлено» / «Ожидает связи»
  / «Ошибка: …».

### PWA

- `manifest.json`: standalone, тёмный фон, иконка `assets/noroot.png` 300x300.
- `service-worker.js` кэширует оболочку при установке и обновляет версию кэша.
- `/api/*` не кэшируется: всегда network-only. Офлайн-откат данных делает `app.js`
  через IndexedDB.
- Service Worker требует HTTPS или `localhost`. Для APK (Capacitor/Cordova) нужен
  HTTPS-контекст или локальный WebView-контейнер.

### Ограничения и открытые вопросы

1. **Иконки PWA 192x192 и 512x512.** Сейчас используется `assets/noroot.png` 300x300.
   Для полноценной установки нужно сгенерировать PNG 192 и 512 из исходника.
2. **QR-картинка.** Маршрут `admin-invitations.js` отдаёт `qrSvg`, если установлен
   пакет `qrcode`. Без пакета клиент показывает ссылку и токен для ручного ввода и
   печати. Установка: `npm install qrcode --prefix server` и добавить
   `"qrcode": "^1.5.4"` в `server/package.json`.
3. **HTTPS и `PUBLIC_ORIGIN`.** Для реального конкурса нужен HTTPS-домен; адрес в
   `PUBLIC_ORIGIN` должен совпадать с адресом клиента, иначе ссылка из QR откроет
   другой origin и cookie/CSRF не сработают.
4. **Резервные копии SQLite.** Файл базы и WAL лежат в `server/data/`. Нужен регламент
   копирования до и после конкурса.
5. **Упаковка в APK.** Планируется через Capacitor или Cordova и онлайн-сервис.
6. **Несколько блоков одного жанра.** Результаты и печать на клиенте группируются по
   жанру; при двух блоках одного жанра данные объединятся. Сейчас блоки создаются по
   одному на жанр.
7. **Администратор без сети.** Админ-панель требует связи: CRUD и приглашения идут
   через API. Офлайн-режим реализован для судьи (просмотр кэша и очередь оценок).

## 5. API (кратко)

```
POST /api/v1/admin/auth/login            {login,password} -> cookie + csrfToken
GET  /api/v1/admin/auth/session          -> новый csrfToken
POST /api/v1/admin/auth/logout
POST /api/v1/admin/auth/password         {currentPassword,newPassword}
GET  /api/v1/admin/state?since=<rev>     {changed,revision,state}
CRUD /api/v1/admin/blocks
PUT  /api/v1/admin/blocks/:id/judges     {judgeIds} — от 2 до 8
CRUD /api/v1/admin/judges
CRUD /api/v1/admin/participants          (+ GET — все активные)
GET  /api/v1/admin/invitations           статус приглашений и устройств
POST /api/v1/admin/invitations           {judgeIds:[...]} -> {invitations:[...]}
POST /api/v1/admin/invitations/:judgeId/revoke
POST /api/v1/judge/auth                  {token} -> {deviceToken,judge,expiresAt}
GET  /api/v1/judge/state?since=<rev>
GET  /api/v1/judge/me
POST /api/v1/judge/scores                {changes:[...]} -> результаты по каждому changeId
GET  /api/v1/health
```

Оценки: `accepted | duplicate | stale | rejected`. Ошибки API — JSON
`{error,message}` без стека.

## 6. Данные и миграция

- Все данные конкурса теперь живут на сервере в SQLite. Клиент не хранит пароли,
  хеши, списки судей или оценки в `localStorage`.
- Старые ключи `lazurny_jury_data_v2` и `lazurny_jury_session_v2` не читаются и не
  мигрируются. Конкурс ещё не начат (11.10.2026), поэтому данные создаются заново
  через админку. Если на устройстве остались старые ключи, их можно удалить вручную.
- `localStorage` используется только для темы оформления.

## 7. Формулы и призы

### Критерии (по 5 на жанр)

- **Хореография:** впечатление/синхронность (соло/группа), композиция, сценический
  образ, школа, костюмы.
- **Вокал:** впечатление/слаженность (соло/группа), сценический образ, репертуар,
  школа, подача.
- **Инструментал:** впечатление/сыгранность (соло/группа), музыкальность, репертуар,
  мастерство, сложность.
- **Театр:** раскрытие темы, впечатление/слаженность (соло/группа), сложность
  репертуара, артистичность, репертуар.

### Расчёт

1. Балл члена жюри = сумма баллов по 5 критериям / 5.
2. Средний балл участника = среднее баллов всех членов жюри блока, которые оценили
   участника; округление до сотых.
3. Если член жюри не оценил участника, в среднем он не учитывается.

### Призы по блоку

| Средний балл | Приз |
|---|---|
| 10,00 | Гран-при |
| 9,00–9,99 | 1 место |
| 8,00–8,99 | 2 место |
| 7,00–7,99 | 3 место |
| ниже 7,00 | приза нет |

### Гран-при по размеру блока

| Участников | Гран-при по таблице |
|---|---|
| 1–19 | 2 |
| 20–35 | 3 |
| 36–45 | 4 |
| 46–55 | 5 |
| 56–65 | 6 |
| далее | +1 за каждые 10 участников |

Одинаковый диапазон даёт одно место всем участникам. Порядок в таблице: по среднему,
затем по номеру. Ничья автоматически не разрешается.

## 9. Полезные замечания

- Не открывайте клиент через `file://`.
- Не публикуйте `server/.env` и файлы `server/data/*.db`.
- Для QR-приглашений указывайте реальный `PUBLIC_ORIGIN` с HTTPS.
- При перевыпуске QR прежнее устройство судьи перестаёт работать: это ожидаемое
  поведение device binding.
